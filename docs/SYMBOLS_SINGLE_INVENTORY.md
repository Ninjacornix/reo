# Single-player overlay: inventory admission and item policy

Static File #1 US research, 2026-11-04. Catalogue partition **o9**, runtime id **9**, load base **0x810000**, owned MWo3 `single.bin`. Continues [actor actions](SYMBOLS_SINGLE_ACTOR_ACTIONS.md) and [planning](SYMBOLS_SINGLE_PLANNING.md). No game, build, replay, network session, live-memory read, attachment or benchmark occurred. These are semantic candidates with verified mechanics, not recovered original names or translated engine code.

Inventory ids appear at actor **+C84..C87**, with additional character-6 ids **+C89..C8C**; current id is **+C7C**. Item instances use **60-byte rows at 0x3C5630**, with type halfword +6, signed quantity/value +24, owner halfword +28 and flags +18. Metadata accessors under 0x5B4380/43F0 and combination check 0x5B3DD0 are separately owned **o2/shared gameplay-overlay routines**, not resident main-image functions. Their overlay availability is caller context and must be preserved when tracing these calls. Names such as ammunition, healing item or weapon are not inferred solely from their flag masks. Candidate item handling returns several distinct codes.

Capacity, ownership transfer, combination and consumption are separate contracts. Several admission helpers return a plan without mutating inventory, while execution helpers can change state before their final status. Runtime optimization or translation must preserve these boundaries and the character-6 extra bank; static confidence does not prove a candidate change safe.
