# Asset registry, reference counts and texture filename routing

Static File #1 US research, 2026-11-04. [Owned identities](FUNCTION_INDEX.md). Only original file-backed bytes and generated instruction comments were read. No game, build, attachment, live-memory inspection or timing experiment occurred.

The registry at **0x341640** contains **256 sixteen-byte records**: packed texture/palette handle at+0, numeric key at+4, metadata halves at+8/+A/+C and signed reference count at+E. Releasing a packed handle dispatches its low and high halves to different resource pools. It is not a host pointer. Initialization clears all records, but bulk release and release-by-handle deliberately begin at slot1.

## Filename/type dispatch

All ranges are hexadecimal and upper bounds inclusive. Table indices use low16 of a1 unless specified; variant groups use its high16. a2==0 selects texture prefix/table, nonzero model prefix/table; direct helpers still index a2 as a table selector, so arbitrary nonzero values are not proven valid.

The owned formats and prefixes at0x255F58..0x256098 corroborate filenames. They do not establish that any particular asset was loaded during a playtest. Current key lookup and filename routing are separate from load/retain, and release paths can synchronously drain rendering. Future caching work must preserve reference-count and drain ownership before removing repeated work.
