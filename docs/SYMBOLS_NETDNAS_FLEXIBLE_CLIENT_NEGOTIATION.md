## Version routing, callbacks and saved prefix

717610 chooses the highest locally allowed advertised version in literal order0301,0300,0002, or reports error when all three disable bits are set. Its wire layout is a legacy two-byte length frame containing type1, selected version, cipher-list length, empty session-id length and16/32-byte challenge. Both random requests' statuses are ignored here; that does not establish failed entropy during actual use. The descriptor serializer and transcript/update routines retain their independently documented contracts.

7178A0 preserves the first7bytes on its own stack before changing method-private buffers. The legacy response predicate checks high bit ofbyte0,byte2=4,byte5=0,byte6=2; it does not decode/validate the entire length/body in this routine. The other response predicate checks byte0=16hex,byte1=3,byte2<2,byte5=2. Those header checks route into other handshake routines rather than confirming a trustworthy peer or complete record. Alert handling checks15hex/3/minor<2 and length0002, reports level/description to optional callbacks and registers an error based on description. No packet was sent or received for this investigation.

The driver, reader and writer retain separate return meanings. Positive prefix output is accumulated progress; successful method installation still delegates the selected handshake. A saved nonpositive transport result can preserve pending bytes for a later caller, but there is no wall-clock bound/watchdog in these bodies. Static loops do not prove a playtest stall.
