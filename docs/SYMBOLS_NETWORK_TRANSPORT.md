The send function0x1C5F30 synchronously copies an accepted packet from the caller into its fixed queue slot. This resolves the temporary-stack lifetime question left by o8 wrapper0x8129C0: accepted packets do not retain that caller buffer. A failed admission still returns0; o8 does not turn that result into reliable retry semantics.

Stop path0x1C6340 reaches an original no-op. The other stop path reaches a separate backend function. They must not be merged under an assumed common shutdown name.

An error in0x1C89D0 does not suppress its copy. Whether valid callers can violate that cursor invariant remains unestablished. The timer helper also mutates hardware state on its first call, so substituting a pure host-clock getter would change its contract. These are static findings, not proven slowdown causes.
