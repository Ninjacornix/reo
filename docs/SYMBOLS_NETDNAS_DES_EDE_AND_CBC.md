## Round loop entry and schedule bounds

7000B8's nonzero-direction counter starts at24 decimal, decrements by8 before each four-expanded-round group, and tests BGEZ after the group: values16,8,0,-8 produce four groups, sixteen rounds. The zero-direction counter starts30 decimal, decrements by8 before each group, and tests BGTZ after it:22,14,6,-2 likewise produce four groups. Schedule traversal uses pairs of u64 slots in forward order0..F0hex or reverse F0..0. These counts follow the actual initial entry, delay slots and terminal branches; callback invocation counts or function size do not determine them.

The eight lookup tables are owned761CC0..762CC0 and fully inventoried in DES_BLOCK_CORE. Each pass mixes schedule words with a half, obtains six-bit indices (including a four-bit rotation for one mix), XOR-combines table results and updates the alternate half. Labels reflect DES-shaped roles and connected method names; neither table resemblance nor this static loop count proves a standard implementation correct.

## CBC lengths, partial blocks and IV ownership

For both CBC routines, the initial length-minus-eight occurs **before** the first full-block test. Ordinary nonnegative lengths therefore execute floor(length/8) full iterations. After those iterations the counter equals remainder-minus-eight. A value of-8 skips the partial block; values-7..-1 select residual1..7. This includes length0: it performs no block transformation and no input/output-buffer access, but still reads and writes the supplied eight-byte IV. It is not a general null-pointer-safe no-op.

Forward residual handling starts from zero halves, reads only the residual input bytes through a backward-loading jump ladder, mixes the chain, transforms and **writes eight output bytes**. Therefore an ordinary forward call needs output capacity rounded up to a multiple of eight. Reverse residual handling **reads eight cipher bytes**, transforms them and writes only the requested residual count through a backward-store ladder. Therefore a reverse call with a residual needs a complete final input block. It advances IV to that complete original cipher block. These are local extents, not an application padding-policy or allocation audit; [cipher context buffering](SYMBOLS_NETDNAS_CIPHER_CONTEXT.md) is a separate caller layer.

Full reverse blocks preserve both original cipher halves before writing plaintext, which supports the ordinary exact in-place path. Arbitrary partially overlapping source/destination ranges have not been proven. Negative or arithmetic-overflow counts are not admitted at entry: the ordinary remainder analysis cannot be extended to them, and an out-of-range partial selector does not establish a safe no-op. No runtime memory fault or malformed-input exploit was reproduced.

The return path clears the16-byte scratch block only. Registers, schedules, IV and other stack state are outside that clearing claim. Neither routine normalizes a success/failure return value.
