# SNAP control payload byte-order layouts

Static File #1 US research, 2026-11-04. Full original main-ELF intervals, owned identity in the [central index](FUNCTION_INDEX.md). These children connect to1DFDA8, the existing [SNAP packet dispatcher](SYMBOLS.md), and are separate from [common record headers](SYMBOLS_SNAP_PACKET_COPY_AND_HEADER_BYTE_ORDER.md). No endpoint, game, test input or native change was used.

All offsets and status values are hexadecimal. The recovered role is selective in-place32-bit byte reversal. Original message/type names remain unknown; changing them to guessed gameplay objects would overstate the evidence. Each row lists the actual offset order, including out-of-order fields.

Counts bounded by37D admit at most decimal892 elements, but this is a numeric count gate rather than proof that the buffer contains that many records. Variable strides use word addition before logical shifts, so invalid size words can wrap. All these functions mutate input directly and do not perform whole-buffer rollback.

Arithmetic right shifts occurring after an00FF0000 mask have the same byte extraction result as logical shifts for that masked operand. That does not make separate converter identities interchangeable: offset sets, execution order and parent layout are retained. No message arrival rate, cost or incident responsibility was measured.
