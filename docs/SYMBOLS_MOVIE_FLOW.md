# SFD movie flow, frame transfer and scenario event records

Static File #1 US research, 2026-11-04. No game launch, attachment, replay,
benchmark, decoder execution, or network traffic was performed. The [central
index](FUNCTION_INDEX.md) records owned main/overlay identities and word checks.
Catalogue partition `o0` has runtime header id1 and load base0x370000.

These mappings distinguish prerecorded `.sfd` playback from in-engine actor
animation in [the animation notebook](SYMBOLS_ANIMATION.md). Movie drop/skip
statistics do not establish original gameplay speed or explain in-engine
cutscene lag. Proposed library and high-level names are inferred; their stated
instruction behavior is the evidence.

## Movie lifecycle and GS frame path

The current context pointer is0x340A20, normally points to0x340A40, whose first
word is the decoder handle. Context+80 stores last polled status,+8C/+8E current
width/height,+91 a mode-specific flag,+96 a service-invocation count. Shared work
pointer0x56BAE8 and texture state0x324405 have separate ownership. Clearing a
flag is not equivalent to stopping the decoder or releasing its texture.

## Scenario event records beside the movie code

Address proximity does not make these movie/audio APIs. The128x24-byte pool
stores linked timestamped event records, with two16-bit arguments and room id
for type2. Serializer0x37E1E0 converts these to the16-byte records at0x8A4CC0 used by
the network overlay formatters; it is documented below.

The16-entry condition branch table was read directly from owned decoded bytes
at0x38CCE0. The `FF` event-table terminators and two64-byte seen arrays are
statically visible; table capacity and data validity are assumed by the loops.

## Investigation boundaries

- Status1 in0x37A5A0 increments a300-call limit. That is a service-invocation
  limit, not proven300frames or five seconds. Its actual cadence must be measured.
- 0x379AF0 performs image-chain submission and synchronization before selecting
  a draw chain. A host optimization must preserve command order, resource
  lifetime, source adjustments and double-buffer selection.
- 0x37B900 ignores its caller's0/1 argument and always clears the same word. A
  guessed setter name based only on callers would have been incorrect.
- Event pool pruning raises a threshold even when no record is removed. It
  intentionally favors higher-priority records; removing that behavior could
  change what is retained for session statistics.
- Library spellings marked candidate come from owned main-ELF diagnostics, not external SDK matching. No controlled fix, measured bottleneck or confirmed
  slowdown cause is claimed. Full decoder internals and remaining o0 entries
  remain separate mapping work.
