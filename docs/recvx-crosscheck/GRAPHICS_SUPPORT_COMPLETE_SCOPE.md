## Useful differences

- CVX `Ps2AlphaIsHalf` stores `(alpha+1)>>1`. Owned Outbreak `0x18E1B0` maps 255 to 128, preserves 0, and otherwise uses `max(alpha>>1,1)`; `0x19E130` uses255-to 128 or plain right-shift when converting toward PS2 alpha. At alpha 3 their ordinary integer arithmetic gives CVX 2 versus Outbreak 1. Sharing a PS2 half-range goal does not make their rounding interchangeable.
- CVX `Ps2BitCount` is a texture-exponent operation built from `PLZCW(value-1)` and subtraction, not a population count. Outbreak `0x19DAC0` narrows signed 16 and searches exponents 1..10, with 1 also retained outside its admitted range. Even input 1 differs: CVX 0 versus Outbreak 1 by these paths. No unrestricted log2 equivalence was inferred.
- CVX `Ps2AddOT` and `Ps2DrawOTagSub` own 4096 buckets, 8192 records, captured texture/bank/TEX0/ALPHA state, and a 64-entry submission texture cache. Special ice-mode texture IDs alter the depth shift. These concrete queue/key/cache contracts prevent replacing an Outbreak Clay/native submission function from the generic name “ordering table.”
- `Ps2ZbuffOff` only emits TEST_1; `Ps2ZbuffOff2` and `Ps2ZbuffOn` also emit ZBUF_1. `PS2_swap` is a fixed GS display copy with a movie-dependent blending constant, not a host presentation API. VU upload helpers select exact CVX program pointers before DMA; no common Outbreak microprogram identity follows.
