# Texture image parsing, pool records and upload preparation

Static File #1 US research, 2026-11-04. [Owned identities](FUNCTION_INDEX.md). Continues the [asset registry](SYMBOLS_ASSET_REGISTRY.md) and [resource residency controller](SYMBOLS_RENDER_STATE_CONTROLLER.md). Original instruction words, magic bytes, local branches and data layouts support these roles. No build, game execution, live-memory inspection, attachment or timing experiment occurred.

Texture/palette records are56 bytes. Texture handles occupy the low16 bits and palette handles the high16 of a packed resource. Pool lookup, record initialization, heap token allocation, payload conversion, residency requests and upload submission are separate steps. These notes preserve the original failure and boundary behavior rather than presenting a safe replacement API.

The image constructors perform payload copying/conversion and can synchronously reach residency or submission work; release may drain outstanding rendering. Those are useful optimization boundaries, but static code does not establish how often they run, whether assets repeat, or which work delayed a captured incident. A future cache must account for packed handles, reference ownership, alpha conversion, resource relocation and mode4 fallback.
