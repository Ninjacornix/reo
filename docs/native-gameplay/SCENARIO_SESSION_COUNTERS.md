# Scenario session counters: interpreter v4

Status, 2026-11-09: native E8/E9 counter ownership and interpreter behavior qualified offline. The whole stock script set, actual providers and game callers remain uninstalled. This extends the independently frozen [v3 flag predicates](SCENARIO_FLAG_PREDICATES.md) evidence.

[SessionCounters](../../game/native/gameplay_scenario/session_counters.hpp) owns one canonical native set of three authored-owner banks with two unsigned32 counters each. It is supplied as a shared interpreter service, rather than allocating a private copy per script channel. A future game adapter must connect the same instance to every participating channel. These are separate from the interpreter's four arithmetic counters and from the shared session RNG/options. They do not advance on host time.

E8 stores a whole payload word. E9 increments the condition ordinal, tests whether the counter was nonzero, and decrements **every nonzero value before deciding success or failure**. Desired nonzero requires a nonzero prior value; desired zero requires zero. Negative original signed values are still nonzero, and arithmetic is preserved as wrapping32-bit state without host signed overflow. A zero value never decrements. Failure invokes the same original condition scanner.

The original helpers call1B02D0 independently: return1 selects the current authored actor bank, while other values select bank0. The ordinary interpreter path uses bank0; the offline path preserves the selected authored owner. Tests set the oracle's mode-getter result appropriately instead of accidentally testing offline helpers with an ordinary-mode double. This does not conflate the distinct runtime mode byte with the unrelated selected-input filter.

Admission explicitly supports indices0/1 and offline owner selections0..2. Larger constant indices are refused while constructing the whole Program; an offline owner outside the admitted profile refuses before execution. The original has no local index checks and can alias adjacent owner/timer state. This native profile must be checked against the actual stock content importer before replacement; the qualification makes no claim that every original out-of-range alias is supported or unused. It does not invent a fourth owner bank.

Both compiler cohorts (`gameplay-scenario-llvm-v9`, `gameplay-scenario-gcc-v7`) pass **111,046 assertions,1,125 actual-original dispatcher invocations and2,634 checked owned instruction comments each**. New cases compare all three offline banks through repeated saved-entry consumption, values0/1/2/80000000hex/FFFFFFFFhex, desired0/1/FFFFFFFFhex, and all four ordinary actor selections selecting bank0. Native snapshots are compared with all six original words on every invocation. Unsupported index admission and offline owner3 refusal are negative checks. All previous ordinary/offline control, flags and resource lifecycle cases remain included.

The current algorithm masks are **271/432 ordinary** and **255/432 offline actor**, including original no-op bindings. Ordinary161 and offline177 bindings remain unsupported. Exact all-binding masks and source/receipt/compiler hashes are in [gameplay_scenario_qualification_v4.json](../../tools/native_reconstruction/gameplay_scenario_qualification_v4.json). A true algorithm bit means the handler is implemented within its explicit native admission profile; it does not prove stock occurrence coverage, provider installation or migrated callers.

No game, window, live process, capture or full game build was accessed. No gameplay speed, rendering path or original timing was changed, and these offline comparisons do not diagnose or fix historical stutters.
