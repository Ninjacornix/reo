# Main owned recipe dispatcher and cooperative events

`OwnedResourceRecipes` implements the complete admitted5B28F0 dispatcher and
5B6740 event consumer through the canonical ResourceRecipes and native update
Owner. Its constructor verifies that both share the same actual World and an
open event pool. No successful event placeholder or private inventory is used.

Both low-byte resource IDs must be active and owned. Compatibility's low byte
selects the original24-entry dispatch, while its full signed value is retained
for the event helper. Reversed operations preserve3-to2 translation; reversed
kind13 instead translates2-to3. KindsF/10 retain the target's old content for
event publication. Nonzero results resolve the owner after the operation, using
the first record if still active and the second otherwise. This resolution does
not assume the original first record survived.

Event publication applies actual local-actor category/slot admission and the
character3/4 recipe tables, including their numeric event codes and argument
narrowing. Requests enter the real cooperative pool with the actual update
counter and room. The diagnostic result distinguishes completed, priority-rejected
and full requests. Ordinary recorder saturation does not change the recipe result
or claim that the event was recorded. Missing/closed required capabilities refuse.

refusal groups. All five owned ITEM banks run, along with controlled dispatch
rows covering all low-byte entries, high/negative aliases, reversed operations,
quantity boundaries, content transformations and selected inventory cleanup.

extra domain and every raw-mode byte are checked, alongside categories0/1/FF
