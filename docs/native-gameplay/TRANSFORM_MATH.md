# Native original-polynomial transform math

2026-11-09: `game/native/transform_math` qualifies on LLVM and GCC against complete original helper execution within the declared FP32 profile. It contains ordinary floats, owned matrix/vector values and immutable original coefficient words. It contains no guest memory, CPU context, emulated registers, original instruction execution or host `sin`/`cos` substitution. This closes the math gate identified in [the earlier motion checkpoint](MOTION.md), without claiming physical PS2 exceptional-arithmetic equivalence or game installation.

The original `18F570` helper uses range reduction, an odd polynomial through degree9, then a signed square root for the complementary component. Native code retains the coefficient words from owned ELF span22FE20..22FE3F, their multiplication/addition order, quadrant behavior, zero behavior and original negative-complement clamp. `191F80` conversion is qualified over all unsigned16 angles actually admitted by the Euler wrappers, including signed actor orientations whose low16 bits wrap. Wider arbitrary32-bit helper inputs are not silently added to that profile.

`370320→1902D0` and `370220→190A10` apply the **same X→Y→Z rotation order**. The distinction is that1902D0 first resets axisXYZ through18FE20, whereas190A10 composes onto existing axes. Both preserve each axisW and the fourth column. Earlier wording suggesting a different Euler order was an inference; these full original-body comparisons establish reset-versus-compose instead. Native matrices retain all16 components so general helper tests can verify those preserved lanes. The actor consumers separately admit affine bases.

Other qualified operations are full identity copy18FDF0, scale construction18FE60, ordered four-term left multiplication191300 with aliasing, and ordered three-term direction transform1919D0. The original identity cache294E00 is runtime-initialized BSS, not a file-backed ELF constant. The required initialized identity profile is established by the owned195E50 store sequence; fixtures seed exactly that profile, and native code owns an immutable identity value. This does not retire the rest of the original initialization routine.

Each compiler passes **2,998,328 checks**: 65,536 angle conversions;73,744 trig inputs including signed zero, subnormal and quadrant-boundary cases;131,072 reset/compose Euler cases whose angle permutations cover every16-bit value on every axis;4,096 full matrix/alias cases;4,096 direction cases; and4,096 scale cases. All comparisons are at float-bit precision, with **983,040** actual original helper calls and checked wrapper call order. Arbitrary unusedW/translation bit patterns, including nonfinite copied values, are preserved without claiming exceptional arithmetic on those values.

The reference executes the actual primary helper entries from byte-verified generated bodies. Its test-only surroundings use the audited SDK131 finite scalar/SIMD operations and the SDK's sign-extending32-bit register setter. The earlier simplified actor fixture's unsigned setter was unsuitable for the trig range-reduction sign test and is not reused here. Unreachable merged source entries remain static identity evidence rather than alternate-entry execution qualification.

The native numeric profile requires binary32 IEEE storage, round-to-nearest and gradual underflow, with contraction and fast math disabled. Finite trig radians are admitted within[-2π,2π]; all wrapped16-bit game angles are inside that domain. Wider radians, nonnearest/FTZ/DAZ modes and nonfinite arithmetic results explicitly refuse. Matrix operations compute private results before publishing them; a refused matrix operation does not export a partial matrix. Control modes are checked rather than changed. Ordinary arithmetic status flags and physical PS2 exception/accumulator precision are not established by this comparison.
