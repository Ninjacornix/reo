# Native typed scene-control activation

Status, 2026-11-09: scenario interpreter v10 qualifies ordinary `104`/`105` and their distinct offline handlers. The native linked owner and three authored-owner saved descriptor banks preserve their command effects. No stock script or game caller is installed by this checkpoint; Stage 4 remains incomplete.

`SceneControls::apply_typed` enables or disables matching live nodes without allocating, resetting or refreshing them. Types 0, 1 and 11 compare the common authored ID. Type 2 also compares its selector; type 3 compares the low bit of its mode. Types 4 and 13 compare a separate selector, while types 6 and 7 compare their own selectors. Other live types remain untouched. Type 4's selector at original `+44` is distinct from the mode at `+64` used by previously qualified commands. Unknown native records tagged as one of these supported types refuse before any command mutation because the missing typed fields cannot be invented.

The apparent extra next-pointer load at `6923C0` in ordinary `105` is unreachable from normal handler entry: type 2 dispatch `692344` reaches `692394` with the type still equal to 2, so its `bne` is false; type 3 dispatch `69233C` jumps directly to `6923C4`. Offline `105` has the corresponding paths at `702420`, `702470`, `702418` and `7024A0`. These conclusions use the owned branch words and complete handler comparisons rather than treating enable and disable as presumed counterparts.

Offline `104` (`7020E0`) and `105` (`702380`) also mutate the selected authored owner's saved control descriptors. Relation zero first applies the live-list command; a disabled shared-list sentinel returns before the saved-descriptor loop. Nonzero relations skip the live list and still process the selected saved bank, subject to the original dispatch table's context filters. Saved descriptors compare their unsigned type and ID bytes to the complete authored words; values above 255 therefore do not silently narrow. Only types 2 and 3 add selector checks. Arbitrary other saved type bytes retain the original generic matching behavior.

[`SavedControlRecords`](../../game/native/gameplay_scenario/saved_controls.hpp) owns those projected fields separately from live linked controls. It exposes three owner banks and an explicit default admission limit of 1,024 descriptors per owner. This bound is a native profile limit, not a measured stock allocator capacity. Unknown trailing descriptor data, stock snapshot import and descriptor consumers are not claimed migrated. The interpreter requires this provider and a valid owner before any operation in an admitted offline program. The offline coordinator checks dependencies before changing selected-owner context or shared flags.

Both LLVM and GCC qualify the complete four original handlers against mixed live nodes and all three saved banks: 136,090 assertions and 13,440 original invocations per compiler, with 449 instruction comments checked against the hash-verified owned overlay. Full interpreter comparisons pass 5,446,265 assertions and 5,639 actual dispatcher calls per compiler. Coverage is 310/432 ordinary bindings and 283/432 offline bindings, including original no-op bindings. The existing 18-command linked-control regression also passes both compilers. These overlapping counts are not totals of unique original instructions or proof of reachable stock coverage.

The oracle contains bounded original register/memory scaffolding only in private test outputs. Production owners use typed native state and contain no MIPS execution, guest RAM access or renderer implementation. Existing optional audio-tick refusal tests remain in the v10 cohort. No game, window, physical audio or performance test is part of this qualification.
