`inventory.py` checks the seven bodies, root initialization/dispatch/confirmation and owned o1 title/options/save-menu bodies. It retains exact instruction evidence, root tables and field offsets. The title and options addresses are admitted only while the owned o1 signature is active; an unrelated overlay at the same address is not substituted. Numeric state IDs distinguish routing and UI policy; an original handler's return zero does not universally mean a successful disk write.

`drive.py` uses the existing read-only owned-process `GuestRam` convention, validates PID + creation identity + canonical private executable/hash, and checks the identity around reads and every input. Card context admission checks its self pointer and distinct outgoing/incoming pointer layout. The driver observes backend result/task/busy values, UI selection/phase/messages, saved options and current brightness. All commands go through the exact case's random nonce and short-lived private-controller file. It uses no global keyboard, guest writes, suspension, focus/window writes or desktop capture. Passive window queries fail the run if the game becomes foreground. UI gates and a bounded action budget replace unverified fixed-delay scripts.

Menu save/load validation first saves through the original UI/backend, changes brightness through the original options screen, loads through the original UI, and checks restoration of the saved brightness. A separate policy route requests AUTO SAVE through its original row and then an automatic save. Save success requires the source-identified completion message/phase, result detail and backend completion; independently captured native entry counters/checkpoints and actual private card files must corroborate it. Handler identity is a source-based inference from the observed root state coupled to native evidence; no direct guest callsite PC trace is fabricated.

`run.py` starts only with explicit approved game/helper SHA-256 values and a new case below `build-native-sjuni/native-gameplay/live/`. The launcher helper uses the existing qualified private import/movie-cache home and an explicit `case/card`, with links refused. It does not select or edit the player's card and enables no progression cheat. The case keeps before/after private-card manifests, the actual owned executable identity, all process/log/driver evidence and native final reports. Original successfully saved private cards are copied before later runs, and their source manifests must remain unchanged.

Controlled failure fixtures modify only a verified copy of that actual primary file before launch. Manifest0's expected file size is `0x3FCC8` (261,320), while the encoded native/original container is `0x3FCC0` (261,312). The unique candidate file must have the verified legacy magic. Error return -1 and ordinary original UI acknowledgement must be observed without a fatal native admission error. A merely missing file does not test the decoder's error return.
