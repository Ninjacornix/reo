# Native item healing/status core and cooperative events

`ResourceHealthEffects` supplies the admitted5B2230 healing/status routine and
5B6610 event producer through canonical descriptors, actors, session and update
owners. It uses the actual native status-clear/message consumer and cooperative
event pool. No health state, item table or event pool is mirrored.

The nineteen stock content300..318 healing amounts are typed immutable metadata
pinned against owned o2 bytes. A reached amount outside that profile is unavailable.
Status8 instead uses fixed300 without reading the table, including for content
outside the amount profile. Signed-halfword narrowing precedes the maximum clamp.
A zero amount can still produce the original successful effect. Auxiliary flag
priority, status-clear selection and event masks preserve original ordering.

The helper intentionally has no activity/quantity/ownership admission of its own;
the outer item-effect dispatcher supplies that admission and remains separate
work. Null target and the original status1E0 gate return before template work.
After a successful effect, event publication resolves the current resource owner
through admitted primaries1..4 and applies the original local-actor gate before
reading the target. Other-target events use1F/character. Same-target priority is
mask8, mask4, special316/317 with mask2, then mask3. Actual pool full/rejection
retains effect success and exposes the dropped event status.

Content312 sets auxiliary1000 once. Its local path clears the actual inventory
owner gate, then requires UI close, feedback selector6 and text notices32/33 at
the original positions. `ResourceHealthUi` is an explicit remaining consumer;
this implementation does not claim the UI/device/text internals have migrated.
Missing consumers report `ui_unavailable` after the known flag/gate prefix.
Other unavailable capabilities likewise preserve earlier field changes rather
than inventing a successful completed operation. Real game installation remains
gated on supplying these consumers.

Complete health/event/status/message/helper bodies execute in the oracle. UI
