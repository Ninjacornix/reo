# Independent native world owner review

Status: read-only source review complete. Root's original-body/lifetime fixture is still the validation authority. No world source was edited by this review, and no game, live process, window or build was used for it. This native component is not installed into gameplay by this review.

The reviewed owner has one canonical `Actor`, inheriting the existing native entity and hit/status/health fields once. Native generational/domain IDs remain independent of guest addresses and the gameplay slot byte. Input frames, session RNG/options, flags and positions are native values. Behavior, AI, pose, scene/grid and publication remain explicit synchronous service ports; their existence does not mean those implementations have migrated.

The current corrected owner shares the same `HitSession` fields for mode, selected actor, pause, room and authority/input filtering. Its references alias that native session instead of maintaining shadow copies. A future runtime integration must pass the same canonical session to save, health/hit and world consumers; the temporary save adapter's guest-seed/options projection does not itself install that world owner.

One concrete teardown issue was found in the first read: implicit member destruction would tear down other world members before the entity store finally destroyed its actors. A derived Actor destructor reentering World could observe a partially destroyed owner that was never sealed. Root addressed this with an explicit destructor that closes while members remain live, and a fail-fast lifetime precondition against destroying an owner during its own synchronous update. The retained review snapshot contains that corrected source. This is an isolated native-owner lifetime issue, not a reproduced game crash or a claimed V39 symptom.

The grid accumulator ordering was checked against actual owned o2 instructions. `66A1E4` calls `6AFE10`, then `66A1EC` loads actor+170, then `66A1F0` adds. The new world's `+= callback(...)` reads the accumulator after the callback and retains callback mutations. The older frame helper's `value + callback(...)` left that operand order insufficiently explicit; root changed it to call the service first and load/add afterward. A meaningful original-body comparison must mutate the accumulator in that port. The old finite-value corpus did not exercise this observer mutation; a prior successful scalar comparison is not evidence for that missing case.

Retirement and reuse use generational lookups and a held `shared_ptr` for the actor admitted to an invocation. Retiring it removes future lookup authority without destroying the object under its active callback chain. Replacements in later unvisited slots are resolved afresh; replacing the current/already visited slot does not invoke that replacement again at the same traversal position. `executing_primary()` identifies a physical slot, not the retained old generation. Services must act on their passed Actor reference or an explicitly retained identity, rather than looking up that slot and silently targeting its replacement. External leases must not retain/use a raw World reference after World lifetime ends.

The update sequence remains contact preparation ? native input routing ? independent nonselected filtering ? authority ? behavior ? local/remote motion and pose ? auxiliary/final motion ? grid ? final actor/notice cleanup. The signed returned versus unsigned stored grid-ID comparison is retained. Pause still services actors, including off-room actors; it is not a blanket freeze. Session gates remain live at the original stages, so callback changes can affect later actors in the invocation.

`input_unavailable` and a throwing service are partial-frame exits: previous actors may already have updated, the current actor's transient resets/AI/contact work can already have happened, and the offline selected-actor reset at the successful end may not have run. RAII clears the execution/reentry guard; it does not roll back the frame. A caller must not retry or fall back as if the invocation had no effects. Reentrant update/close must produce the documented busy outcome, while explicitly admitted slot retirement/replacement remains possible inside callbacks.

World, shared Session and mutable controller spans need a simulation-owner-thread contract. The entity store is explicitly single-owner-thread; returning native mutable spans does not make concurrent host-input writes or independent session updates safe. Publication from input/monitor threads must use a reviewed handoff rather than racing the world arrays. No additional concrete field/order mismatch was found in this review, but this is not proof of every service implementation or lifetime outside the stated contract.

Root's planned tests cover destructor reentry while members are live, destruction-during-update rejection, accumulator mutation, partial-frame errors/reentry, retirement/replacement generations and original-body ordering. Component qualification and actual game/caller integration remain separate; no full native actor, AI, animation, rendering or world-installation claim follows from this review.
