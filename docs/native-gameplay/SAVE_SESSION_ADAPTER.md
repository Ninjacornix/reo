# Native save/session entry adapter

Status: implemented and qualified offline for an explicitly selected File #1 candidate. Actual game acquisition, save UI/card operations and a game save/reload have not been tested by this adapter qualification. Stage 4 remains open.

`recomp/overrides/native_gameplay/save_session.cpp` replaces nine complete entry points with the already qualified native save/session cores. Guest registers, RAM addresses and generated function calls remain in this adapter; they do not enter those cores. This is an explicit temporary projection of legacy game state, not a native world owner.

| Original entry | Selected native behavior |
| --- | --- |
| `1C5410` | Capture from the context's **E8** buffer pointer; original timestamp observer, native section assembly and shared native RNG, exact legacy encoding |
| `1C55C0` | Restore through the distinct **EC** pointer; original signed return `0`/`-1` and checksum-failure payload mutation |
| `1C5630` | Root modes 0/1 clear the second flag before the second section; other modes do nothing |
| `1AEC50`, `1AEC80` | Shared two-stream RNG initialization/requests, including reads and unsupported selector result zero |
| `1AED60`, `1AEDB0` | Saved option defaults/notification and capture preserving unknown bytes 8..15 |
| `1AEE40`, `1BADF0` | Native option bounds and restoration through the existing screen/audio observers |

Admission and lifetime

The bootstrap must check File #1 identity (`SLUS-20765`, entry `100008`) and `REO_NATIVE_GAMEPLAY_SAVE=1`, and pass `selected_candidate=true` to `reo::native::native_gameplay::install_save_session_before_run`. Compilation requires `REO_BUILD_NATIVE_GAMEPLAY_SAVE=1`. Merely including the header does not select it. A false selection leaves registry/state untouched.

An actual pre-run lease precedes registration. Admission checks fifteen original entry/provider text ranges, the immutable defaults table, and exact registry function pointers. `image.inc`, `entries.inc` and `providers.inc` are derived and rechecked against owned ELF SHA-256 `06bd5fd7243144cd30cdd0c0023763a369738cb91b177b35e85f6a4782b4ca46`. Original text is read only during the pre-run image check. Live state uses bounded bank-aware `copyBytesForBank`, inside an actual adapter `EntryScope` and genuine guest-execution depth.

Each runtime has its own strongly retained `ExternalWorker` binding and serialized operation admission. No extra OS thread runs gameplay. Stop prevents further adapter bank transfers; join drains a currently accepted synchronous observer and unregisters the binding before RAM can be released. Join called inside that same operation refuses instead of deadlocking. Partial registry publication rolls back. A stale registry/provider, foreign RAM/runtime, missing guest execution, interior continuation, reentry, bounds violation or failed observer stops the selected runtime visibly. There is no original-function fallback after native effects.

Ordering that must remain explicit

Capture invokes the real timestamp entry `1BF660` against the guest header first. It then rereads the container and imports live state, retaining changes made by that observer. Prepared plaintext is published before the primary shared RNG advances; the encoded container is published afterward. Guest seed fields remain the temporary interoperability boundary with unported consumers. Requests reread them and write only the selected advancing stream; initialization retains the original observed/secondary/primary store order.

Restore publishes the decoded container and new 16 saved option bytes before the option observers. The screen callback sees all eight live values already installed. Each following callback sees values reread after preceding observers. After notification, both live state and the decoded guest container are refreshed: original header flags and later section helpers read those bytes after notification, so observer edits must survive. The private container must not overwrite observer changes afterward. Failed checksum still publishes the fully decoded payload without notifications; failed magic leaves it unchanged. A failing noexcept settings bridge records failure and suppresses subsequent guest flag/data exports, even though private core calculations can finish while unwinding that boundary.

The timestamp, defaults notification, screen and three audio callbacks still use the six original provider entries. The adapter calls them synchronously using the same actual context, original return PCs and matching original stack depth, including the nested save restore/header/options depth. It restores the actual caller context around those calls and rejects a yield, wrong PC, unbalanced stack or lost execution admission. Hook returns preserve other register values; RNG returns V0 and restore returns signed V0. Transient contents of dead caller frames and unspecified volatile register residue are not reproduced. The eighteen source-verified save caller sites show capture returns are followed by `1C09D0` with freshly loaded arguments and second-section clear returns by capture; neither uses V0/V1 as a result. This inventory is evidence for those ABI contracts, not a claim that all callers/scenario code have migrated.

Qualification

Both LLVM and GCC pass **1,543 assertions and 227 original/native entry comparisons** across all nine hooks. The reference side executes the actual generated original function bodies, with all instruction comments checked against the owned ELF. Full 32 MiB RAM comparisons exclude only dead stack-frame bytes; callback ordering/arguments/stack depth/return PCs and defined return values also match. Provider ports are explicit offline doubles, not measured game timestamp/audio/screen behavior.

The cohorts cover timestamp and option observer mutations, decoded header/data changes during notification, conditional-tail retention, E8 versus EC, plaintext visibility before RNG, guest-written seeds between native requests, all selectors, unknown option bytes, bad magic/checksum, disabled/late/wrong-image admission, missing/replaced originals, worker refusal, registry rollback, independent runtimes, wrong runtime/RAM/depth, bounds/alias refusal, stopped/stale hooks, reentry, provider errors/yields, preserved registers and join draining. A failed settings observer verifies decoded/settings publication before the observer and absence of later live flag/data effects.

Both compilers also compile the actual adapter translation unit against the audited SDK131 without fixture headers, producing actual objects from **52 consumed project/SDK inputs**. Dependency provenance is `dependency-muted-rna-reapply-v1-receipt.json`, SHA-256 `9f1e67e084ed94fb3e41bf6b1a3f013dcb43aaef15b6a82b06f56a261573a67c`. The older active submodule was neither modified nor used as this SDK. This compile check does not prove actual runtime ownership acquisition or provider execution.

Final receipts and exact source/evidence hashes are bound by `tools/native_reconstruction/native_gameplay_save_session_adapter_qualification.json`. Failed and superseded private cohorts remain: early fixture setup reused a clobbered original A0, a fixture failure assertion captured the wrong entry PC, an alias-provider double lacked bank translation, negative diagnostics initially confused JSON parsing, GCC required an indentation correction, and the first actual SDK compile exposed its bank-aware register macro's required `rdram` local. The observed-cohort diagnostic-failure fixture also retained cross-CRT closed-descriptor/error-flag experiments; the final test uses a read-only stream and checks the actual write return as well as the stream error flag. Final sources pass both complete cohorts; these retained failed folders are not game crashes.

Bounded invocation evidence

The observed revision retains nine atomic accepted/completed/failed/rejected counters, completed restore result counts, and a fixed 128-row native checkpoint ring. Admission failures and reentry are rejected; accepted calls resolve into completed or failed before join. The original helper invoked internally by native save restore is not falsely counted as another entry-hook invocation. RNG requests contribute exact counts and no per-request trace rows. A binding ID identifies each single final join dump. The dump says whether installation finished, reports retained/overwritten row counts, and emits no I/O during gameplay. Trace timestamps are host observations of checkpoint order, not guest simulation time or a performance benchmark. Diagnostic output failures do not alter gameplay state or quiescence.

`tools/native_reconstruction/gameplay_adapter/observations.py` parses only explicit invocation evidence. The fixture independently tallies 321 accepted, 312 completed, 9 failed and 5 rejected observed calls; 113 drained binding dumps; 11 complete capture sequences and 8 successful restore sequences. A deliberate history overflow retains 128 rows and declares 192 overwritten rows. Repeated joins emit once, and a deliberately read-only stderr stream still permits unchanged state and a successful join; its absent dump is explicitly not counted. An empty or partial game log cannot prove invocation. The prior unobserved qualification is preserved byte-for-byte as `native_gameplay_save_session_adapter_qualification_v1.json`, with exact old sources/docs retained privately under `build-native-sjuni/native-gameplay/adapter-pre-observation-v1/`.

Remaining integration boundary

The root task owns bootstrap/global CMake/preparer wiring and actual candidate testing. That work must check selected installation and exercise gameplay RNG/options plus ordinary save/reload through the actual caller/UI/backend path, with unchanged default-disabled behavior. The adapter deliberately refuses overlapping container/live-state projections, odd containers, invalid bank ranges, reentry and guest-yielding providers. These unsupported inputs receive visible failure rather than invented semantics. Native ownership of the entire live state, card UI/filesystem, timestamp implementation, rendering/audio observers, scenario/entity callers and the rest of Stage 4 remain separate work. No game, live process, window or service was accessed for this qualification, and no commit was made by this subtask.
