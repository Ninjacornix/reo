# Native resource companions

The six5DF450 resource families now construct and update real native visuals
through the existing168-work/256-child owner. `ResourceFactory::bind_companions`
requires that visual owner to be bound to the same World, descriptors,64-model
owner and templates. Its actions reach the actual native resource-audio frontend,
bank mixer, canonical scheduler and shared64-light owner. Missing or foreign
bindings still refuse construction. These are native components; the installed
game remains V39 and Stage4 is incomplete.

The [audited content table](RESOURCE_COMPANION_AUDIT.md) identifies the seven
emissions across six contents. Constructor variants are all zero. A2 supplies
the child-enable mask:3200 usesFFFF and the second1D emission uses20; these are
not random/32 animation variants. Complete constructor comparisons caught that
error in the new implementation. The shared general sampler supplies transforms,
material tracks, angle/scale composition and camera offsets. The qualified
654720 policy supplies attachment, action waiting, looping, random delays,
retirement and fading. It samples children at the pre-increment time. Fading
adds the negative fade delta and clamps each material scalar to0..1.

Companions retain the real model object. Model retirement clears that object;
its lease can finish a fade without retargeting a reused model generation.
Descriptor owner tags1..4 resolve the canonical primary actors, including
inactive stored actors as in the source. Other tags mean no actor in this
specific callback. Actual World/resources/models/templates/actions are borrowed
and must outlive the visual owner and its synchronous callbacks. Published frames
retain immutable banks and child values. The optional category is an explicit
override: the final emission gets1C; the first1D emission retains the constructor
default rather than receiving that assignment.

Resource cues20/21 go through `BasicAudio::resource`; ignored bank outcomes stay
available as `last_audio`, not a fabricated successful sound. Light requests go
through [TimedLights](TIMED_LIGHTS.md), using the canonical actor material byte.
Known full task/light capacity is retained in `last_light`. Full light capacity
rolls back its new task and allows the visual to continue. Closing or erasing a
timed task releases only its light. No parallel effect, child, model or light
pool is introduced.

Two unsafe source cases have explicit modern behavior.3200 argument0 writes
before checking a missing/full visual pointer; native construction returns the
known absence without a null-address write. The timed-light source can retain a
null light after allocation failure; native code rolls that task back. Recycled
actor/model/light storage cannot retarget retained native capabilities. These
policies are not claimed as bitwise equivalence to invalid pointer accesses.
