# Canonical native local motion and affine pose consumers

2026-11-09: `integrate_local_motion` and `rebuild_actor_pose` now implement the complete outer `65E3A0` and `65E4A0` policies using the [qualified native transform math](TRANSFORM_MATH.md). Both compilers match the actual original outer bodies plus their full original math chains. The required surface-orientation operation `6657B0` remains an explicit native provider. No game launch, native World installation or whole Stage 4 completion is claimed.

`65E3A0` consumes canonical orientation, root-motion delta, model scaleX/Z, multiplier and position. It builds the original reset-axis rotation, applies B4/1/BC scale only when control mask0x8 is clear, clears that mask before vector work, transforms the root delta, multiplies all three components by F0 and then adds to position componentwise. It does not consume the root delta or add wall-time scaling. Model scaleY is not read. Skipped scaleX/Z values are also not required; a specific comparison admits nonfinite unused scale values under the original skip mask.

`65E4A0` resets the canonical basis, computes the yaw-only candidate direction A8 and composes the full orientation into the basis. It transforms local impulseD8 and uses the exact `position + (transformedLocal + worldImpulseE4)` addition order. Both impulse vectors are cleared **before** the required surface provider. The callback receives the canonical Actor, can mutate position/basis/direction/impulses/orientation, and retains those changes. Final basis translation is read from the **post-provider** canonical position, never a stale private pose snapshot. No extra normalization is introduced.

The new routines use the existing canonical `position`, `orientation`, `candidate_direction`, `model_scale`, `motion_multiplier`, `local_impulse`, `world_impulse`, `root_motion_delta` and collision basis. They do not copy an Actor into a shadow state. Temporary matrices/vectors are mathematical values. `pose_ready` is an explicit native capability invariant: local movement/incomplete pose invalidates it, and a successful finite affine pose publishes readiness only after the provider and final translation. Provider/numeric/profile failure leaves prior effects visible and cannot trigger an automatic legacy retry.

`MotionTransformFrameServices` intercepts real canonical World local-motion and pose stages and composes with the earlier `MotionFrameServices` auxiliary/finish interceptor. Both the ordinary local path and the remote-motion path are checked: remote motion skips local root integration while still rebuilding the impulse pose. Remaining behavior, remote admission, geometry and surface owners are required providers without successful default implementations. Borrowed providers must outlive their adapters.
