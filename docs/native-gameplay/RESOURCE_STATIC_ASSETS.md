# Native static resource poses

`ResourceStaticAssets` imports the owned NBD forest section and constructs static
world poses through the existing native Skeleton/Instance pipeline. It owns
immutable content keys, root ordinals and admitted part poses, replacing the
mutable source matrix-cache dependency for the reached primary consumer. Lookup
preserves complete372490's signed16 comparison, first matching root and-1 miss.
Imported poses remain valid after their cache and input bytes are released.

The source1D3100 body executes completely in the isolated oracle: root packing,
resource clone, static node construction, world rebuild, matrix publication and
temporary resource release. Native root count, IDs, per-root counts and admitted
primary matrix outputs match. The second bind-matrix bank is not supplied by this
native component. The declared source heap/cache bookkeeping ports model bounded
private allocation and resource lookup; no original CPU or guest RAM exists in
the production importer.

Both compilers pass3,399,229 checks. Four owned DEF NBDs and twelve distinct owned
OBJ NBDs contain90 roots;184 admitted matrices compare bit for bit. All65,536
signed lookup values run against every file, totaling1,048,576 lookups. Two roots
contain more than six part matrices. Their keys/counts remain known, while
`parts` refuses to bind them to the current six-part ResourceModel contract.
This is not a claim that those roots are absent, nor a repair of any source
layout aliases. The import admits at most96 roots under the measured source
profile; broader asset profiles require separate work.

The82 refusal checks include those two large roots, invalid indices and truncated
NBD input. Retained pose lifetimes, existing native visual/task/camera behavior
and concurrent immutable frame readers pass in the same cohorts. Both parent
libraries compile. Evidence in `native_resource_static_assets_qualification_v1.json`
binds exact files, original instruction-word audits, input selection, compiler
identities, source copies and outputs. No game was launched.

The importer is ready for the admitted primary construction path. Actual factory
and asset-loading callers, the larger-part consumer contract, remaining callback
families, renderer handoff and complete Stage4 acceptance remain open.
