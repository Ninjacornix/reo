# Canonical native three-probe surface orientation

2026-11-09: the complete `6657B0` consumer now has a native implementation, `update_surface_orientation`, with a concrete `GridSurfaceOrientation` provider for the existing native pose pipeline. The production code consumes canonical World Actor fields and the existing owned immutable collision Grid. It has no CPU context, guest addresses, instruction interpreter, generated-function API or shadow Actor. No game launch, installed native World or whole Stage 4 completion is claimed.

The original return has two meanings: **1 means no requested work; 0 means processed**, including a rejected/cleared blend. For categories 0/1, status BA0 bit8 can start a blend by setting flags548 bit1 and the owned B94 rate 0.1. Other categories require that flag already set. B90 is incremented first, then clamped at zero only for a nonpositive rate, or at one for a positive rate. An unrequested branch does not inspect unused position, basis or blend floats. There is no elapsed host-time multiplier.

The three owned offsets are `(0,0,-40)`, `(0,0,40)`, `(0,0,40)`. Their yaw turns are respectively `yaw`, `(yaw-0x71C)&0xFFFF`, `(yaw+0x71C)&0xFFFF`. Conversion uses **`(ownedTau * float(turn))/65536`**, preserving a different operation order from the already qualified generic Euler conversion. Rotation uses the original polynomial through native math, without substituting `std::sin`/`std::cos`. The cosine threshold uses the original `370100 -> 1921A0 -> 18F470` turn scale and polynomial; exhaustive comparison covers all 65,536 turn values.

All three offsets are rotated and translated by current position **before the first floor callback**. Then three ordered floor queries use required type FF, at the translated Y coordinate. The consumer replaces each point's Y with the returned height even when the floor class is FF. It does not silently substitute the actor's height, use the center-height cache or add a new hit-class gate. `SurfaceOrientationFloors` exposes the required native query seam; `GridSurfaceOrientation` supplies the real qualified `response::Grid::floor(point,255)` implementation. The borrowed Grid must outlive its synchronous provider.

The cross product of the two sampled edges is computed before the rejection gates. Either absolute height difference from the first point greater than 80 clears flags548 bit1 and sets B90 to positive zero. Otherwise the **stored canonical normal178 dot up** is compared with `cos(turn0x100)`: values **greater than** the threshold clear the blend; values at or below it proceed. This avoids applying a slope blend to an almost upright stored normal. `0x100` is 256 turn units. The stored normal gate is distinct from the newly sampled cross product used to construct the target basis.

Accepted work follows the complete `191740` normal/heading basis construction and `191900` weighted blend/reorthogonalization. The target normal and canonical candidate direction A8 are normalized; the right axis is their ordered cross product, normalized, and the third axis follows. Old and target translations are zeroed. The final weight is reread from the canonical actor after floor providers, and old/new X/Y axes are blended, normalized and reorthogonalized in source order. Output translation is zero here; the enclosing qualified `rebuild_actor_pose` publishes the **post-provider current position** afterwards. Temporary vectors and matrices are mathematical values, not duplicate actors.

The finite FP32 profile uses round-to-nearest, gradual underflow, disabled contraction and no fast math. Separately rounded multiply/add/subtract order matches the audited SDK131 original-body profile. Zero/parallel-vector normalization retains that SDK profile's max-finite reciprocal-square-root fallback and can yield a degenerate basis; it does not invent a replacement axis. Nonfinite consumed state, arithmetic overflow or an unsupported FP control profile fails visibly. Physical PS2 exceptional values, exception flags and accumulator precision are outside this qualification. Floor/provider failure preserves earlier blend/position/impulse effects, leaves the enclosing pose unavailable, and never retries a legacy function after effects.
