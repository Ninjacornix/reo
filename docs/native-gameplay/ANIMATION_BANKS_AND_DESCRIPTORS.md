# Native motion banks, descriptors and model-bank blending

2026-11-09: three native owners now replace the resource-token/pointer representation at the next animation boundary: `MotionBank` retains immutable raw motion blocks, `File1MotionDescriptors` holds concrete immutable lookup metadata, and `PoseBlend` operates on independently mutable model banks sharing one immutable Skeleton. This is an offline qualified component, not a running native World installation. Actor track configuration/ticking and descriptor application are the next layer; attachments and linked objects remain separate.

`MotionBank` reproduces full sparse construction1D16C0/1D1940/1D19D0 and strided1D1500/1D1960/1D1990 indexing. Sparse modes0/1/2 use original physical cursors5/1000/5. It preserves the logical-to-physical row map, absent entries, partially populated rows, repeated loads and old live slots that the source does not overwrite. The physical token area and logical map each have2000 slots under this admitted record profile. Strided construction uses200 or500 while lookup deliberately retains the source's literal200 quotient stride. Source offsets and authored track range are checked; nonterminating original16-bit count overflow, out-of-record indices, zero width and unsupported modes fail explicitly.

Original raw-block mutation and16-bit heap identities become native shared ownership, not emulated kernel objects. A shared immutable `MotionBlock` retains the exact source bytes and identity; its Clip is decoded lazily only when requested. This admits a bank containing an unused unsupported curve without pretending that curve can play. Existing Clip admission still rejects unsupported consumed data. Bound Clips and block leases survive bank replacement/destruction. Mutable bank loads and lazy decode belong to the serialized native resource/simulation owner; no arbitrary ByteView or I/O runs in these methods. Staged validation avoids replacing an existing bank on malformed input; no parity claim is made for original malformed-memory behavior.

The bank oracle executes six complete original constructor bodies. Raw packing1D3550, resource duplication192500 and release1925A0 are declared provenance/token seams. It compares every physical slot, every sparse logical row and116,000 actual query-index results. It observes original raw-block memoization and1161 releases, but does not claim to implement or requalify the old PS2 heap. Full raw Clip conversion/sample comparisons are independently supplied by the existing animation corpus qualification. Assets are entire hash-checked pc_000.bin/pc_001.bin plus actual archive members NETBIO00.DAT/0/735(b00),/757(d00),/758(d01). Their duplicate basenames do not establish a particular cutscene/room identity.

`File1MotionDescriptors` replaces original runtime pointer tables with native index arrays. The concrete profile contains88 direct-map entries, class-map row counts118/122/20/20,144 state-map rows and568 packed descriptors, sufficient for every index referenced by these admitted maps. The first64 resource records have matching byte6 ordinals0..63; their byte4 selector is retained exactly. This is a bounded admitted profile, not a claim that arbitrary record64+ is valid. The generated include is reproduced from owned o2 bytes and bound to full original5D4570/5D46C0 instruction proofs.

Lookup preserves ordered BA0 overrides: mask18 selects state3, then mask20 selects state0. Families1/2/3 use their respective maps. Every other family returns descriptor zero; its low12 bits are ignored by the actual branch. Raw class bytes remain literal linear table offsets while the resulting index stays inside the admitted table; the native code does not silently coerce every class to0..3. Unpack preserves single-level familyF redirection and the category-one coercion rule. Its two12-bit motion keys, offset/shape selectors, packed flags and threshold bytes are separate typed values. The two untouched original scratch-padding bytes are not invented semantic fields. Original unbounded indirections outside the admitted profile fail visibly.

`PoseBlend` implements actual192690/192710 and191900, including weighted scale parameters, weighted translation, independently normalized X/Y inputs, cross-product normalization and rebuilt Y. It is not SLERP and does not normalize or clamp supplied weights. Traversal starts at the first matching track subtree and preserves the source sibling boundary. Matching banks must retain the same authored Skeleton identity. Actual5D42D0 copies only local matrices and three scale parameters into the secondary bank;5D43C0 copies immutable motion bindings and ten per-node caches. These operations do not copy an Actor, a whole pose state or a second canonical actor basis. The flat original low-byte counter is admitted only for at most255 nodes. A helper creates a fresh secondary Instance sharing that same immutable Skeleton.

Mutations invalidate the destination's current ready joint snapshot; retained prior publications survive. Sampling the copied binding after5D43C0 proves that it retains the actual Clip and cache owner, rather than merely matching a superficial pointer value. The narrow existing-model change is a single `friend class PoseBlend` declaration; model.cpp and all prior behavior remain byte-identical to the constraints checkpoint. The finite strict-FP profile remains RNE, gradual underflow and no fast math/contraction. Degenerate finite bases follow the qualified SDK normalization fallback; physical PS2 exceptional flags remain outside the claim.

Both compilers pass **188,768 bank checks** each:17 whole-bank cases,5495 live-slot comparisons,116,000 query comparisons,2283 pack-provenance seam calls,1161 release observations,six retained-owner cases andtwo malformed/mode refusals. Both pass **253,312 descriptor checks**:62,384 complete original lookups,22,224 complete original expansions and11,328 explicit out-of-profile refusals. Both pass **729,410 pose-blending checks**:1416 real clip-bank blends,118 pose captures,118 binding/cache captures,4096 independent matrices including degenerate vectors,218,196 joint comparisons and670,456 original calls.

The source-discovery failures are retained. No game fault, runtime slowdown cause, measured optimization or full actor playback is inferred from these offline findings.
