# Shared scenario control and collision-proxy installation gate

Status, 2026-11-09: the canonical shared owner is now implemented and independently qualified; see [shared owner results](SCENARIO_SHARED_PROXY_OWNER.md). The complete room importer and actual game installation remain open Stage 4 gates. The following design rationale records why historical standalone projections were insufficient.

The original global pool is shared: `5C1120` clears exactly 128 records of `C4` bytes, resets the signed free count at `3B5150` to 128 and the list pointers at `3B5158/3B5160`. `5C11B0` allocates and links those records; `5C12A0` retires them. `5C1390` populates geometry plus type-dependent payloads from relative room records. The script handlers and `5819C0` traverse the same `3B5160` list and consume those payloads. Native logical control and collision geometry must therefore share one identity, activation/type state, capacity budget, order and retirement policy when installed. Copying them into parallel mutable registries would violate that ownership requirement.

The current native SceneControls owner intentionally projects only fields needed by its qualified command/query profiles. Its configurable standalone capacity is not evidence of an original independent 1,024-record pool. The native collision proxy owner preserves the original 128-slot capacity and geometry lifetime; this alone does not prove it owns every script control payload. Historical standalone results remain valid under their declared profiles.

After the actual matrix-program consumer, the next required work is the complete bounded `5C1390` relative-record importer and a unified typed control/proxy record owner. Preserve original first/last query and prepend/append ordering, allocation failure, missing resource/remap handling, shared activation mutations and retained native leases. Test real owned room resources and cross-consumer effects: a script activation must affect the collision consumer of the same native record; retirement must invalidate both views; neither side may acquire extra independent pool capacity. Unsupported source indexing remains explicit rather than writing adjacent native state.

The related matrix-program work is a separate **16-channel** owner at original `4A3620` with stride `60` hex. `5D7D60` clears 16 such records and `5D7F00` services 16; channel 16 would alias saved model poses at `4A3C20`. The existing 32-bit SceneChannels render-admission mask does not establish 32 matrix-program records. The new canonical channel will contain the collision RouteChannel gate/active component once, alongside its program/matrix state.

`6B5C60` selects and initializes an immutable curve program, binds a native model matrix and updates channel state. It performs no room/archive/file I/O. Its descriptor base is `70B190` (the signed `ADDIU B190` after `LUI 71`), not `71B190`; its type-two mode byte is `+71`, not `+69`. The remaining evaluator, model binding and actual consumers must be qualified rather than replaced with a successful callback.
