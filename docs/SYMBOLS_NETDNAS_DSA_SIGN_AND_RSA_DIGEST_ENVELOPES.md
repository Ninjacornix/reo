## Arithmetic, reuse and error boundaries

726500's key20/24 cache is consumed only when both pointers exist; it clears both fields before continuing and frees the transferred values on the common exit. A single nonNULL cached field remains owned by the key while the provider generates a new pair. The sign-shaped arithmetic uses key10 as modulus, key1C as private multiplier and the generated pair as inverse/r material. This is a supported local interpretation, not a formal DSA proof or a guarantee that all imported digests and keys are valid.

7267E8's random loop tests for zero after an optional one-time subtraction of key10 and repeats through the random generator. It does not run the loop merely by counting helper invocations: initial generation, comparison/subtraction and zero checks were all inspected. It transfers the computed power result to a3 and inverse to a2 after releasing preexisting output pointers. Aliased output cells or aliases to key fields are not admitted locally. No nonce operation or random-source test was performed.

726A50 constructs the digest envelope without taking ownership of the registry descriptor or caller digest bytes. Encoded length is checked against modulus span before allocation, but child buffer adapters still pass their own all-ones capacity contract. 726BE8 only compares the parsed algorithm ID and OCTET payload after recovery; the presence of those checks does not establish protocol authentication, full DER canonicality or padding validity beyond the child provider's unverified contract.

All arithmetic/codec instructions in these bodies were read.
