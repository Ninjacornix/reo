## Startup and callback boundaries

Startup clears exactly the half-open BSS span259D80..8AA380 in the literal owned body. Its initial addresses are16-aligned; byte alignment/tail paths remain part of the complete routine rather than inferred extra clearing. Some addresses are BSS/guest memory rather than file-backed data; instruction evidence is from the owned ELF. Reconstructing the startup body does not authorize running it or guarantee that native launch executes every original syscall.

The100220 catalogue interval contains both an inline thread-exit syscall and an independently entered callback-registration body at100230. A normal nonreturning kernel exit and a registration call must not be merged into one guessed user-facing feature. Neither catalogue splitting nor a new function denominator is introduced. Likewise the worker’s114460 exit is a delegated lifecycle contract; the following source path is still preserved if that child returns unexpectedly.

Both callback routes save the caller GP when installing a function and restore the appropriate GP around invocation. This is original guest ABI evidence, not proof of C++ thread-safety. Worker teardown signals its stop flag then deletes shared semaphores without locally joining the worker; no race or hang was reproduced. Callback state ownership and active native overrides require separate runtime/build evidence before any fix.
