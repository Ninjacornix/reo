The three literal software-double constants are assembled in registers, not read from an unverified external table: `81E0 <<47 =40F0000000000000`, `83E0 <<47 =41F0000000000000`, `F7C0 <<46 =3DF0000000000000`. They support the2^32 word decomposition and its inverse. The low-word conversion helper1124C8 returns a uint32 bit pattern sign-extended in a64-bit register; these callers explicitly shift/mask it before combining, so a negative register is not automatically a negative numeric unsigned32 result.

The unsigned reconstruction’s negative-high-pattern path computes `(highBits>>1) OR (highBits&1)`, converts through the signed64 helper, then adds that double to itself. That sticky-half route avoids passing a high-bit-set unsigned value directly as a positive signed64 value. Residual conversion uses a separate comparison and possible subtraction. It must not be collapsed to a single guessed instruction or used as evidence that a downstream caller expects ordinary integer ABI values in every context.
