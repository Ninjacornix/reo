Every converter first loads context48 input pointer. Phase4==1 may work only while predictor8's phase134F98==0. It invokes output-reservation callback78(context7C,&offset68,&budget6C,&budget70), ignores callback return, then computes **N=min(context60-context68,context6C,context4C)** using signed comparisons. Third callback-written budget70 is not used by these converters. Output left/mono pointer=context5C+2*offset68; right=context5C+2*(context64+offset68). No extra input extent or channel-array capacity check.

SignedN<=0 skips all sample loads/stores but still publishes N and consumed-byte arithmetic, including negative values if caller contracts admit them. Positive loops all test before their first read. Channel byteE is signed for branch/accounting; exactly2 selects stereo, all other values select one mono copy route yet byte count still multiplies by the signed channel value. Malformed channel values therefore cannot be normalized to1 in a faithful rewrite.

After conversion sets phase4=2, result90=N, result94=the documented input-byte count. The same call then processes phase2: callback80(context84,bytes94,samples90) and sets phase4=3 regardless callback return. Entry already atphase2 skips predictor/reservation/sample work and completes that callback directly. Other phases return. None of these workers advances the input pointer or publishes SJ output chunks directly; [outer publication](SYMBOLS_ADXB_HEADER_INPUT_AND_OUTPUT_SERVICE.md) owns those steps.
