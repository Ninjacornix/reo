## Representation and loop admission

Observed big-integer layout: next0, size class4, limb capacity8, signC, used count10, little-endian32-bit limbs14 onward. The class cache is reent4C; reent48 is a different linked cache for625 and repeated squares. Reusing a record clears sign/used but leaves limb storage and allocator metadata. Allocation requests use guest32-bit shifts/additions and depend on valid class ranges; they do not prove size arithmetic safety.

Arithmetic routines frequently assume used>=1 and nonNULL allocation results. That is retained explicitly: scalar multiply/add and left-shift copy loops execute an initial body before comparing their end/count; magnitude comparison with equal zero counts reads before the payload. Conversely whole-result clearing and top-zero normalization in the multiplier have initial gates and may skip safely for zero extent. No generic underflow hypothesis is substituted for actual loop-entry control flow.

The powers-of-five routine uses arithmetic right shift, so negative exponents are outside its locally admitted ordinary domain. The source has no rejection branch for them. Cached-square pointer links and freelist pointer links reuse offset0 for different object populations; their ownership must not be merged. Several paths recycle an input after publishing a replacement, while ordinary multiplication and difference retain both inputs.
