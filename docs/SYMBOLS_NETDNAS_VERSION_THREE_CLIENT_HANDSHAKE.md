## Driver stages and progress

Initial states 0x1000/0x1003/0x4000/0x5000 allocate/grow handshake storage, ensure record buffers, prepare the buffered backend, initialize two transcript digests and select 0x1110. Renegotiation state 0x3004 sets the renegotiation field and returns through initialization. The ordinary sequence is ClientHello, ServerHello, certificate, ServerKeyExchange, CertificateRequest, ServerHelloDone, optional client certificate, ClientKeyExchange, optional CertificateVerify, ChangeCipherSpec and Finished, then peer Finished. Resumption reads peer Finished earlier and sends the local final flight afterward. This ordering follows calls and explicit states, not captured traffic.

The message-reuse flag 0x168 and the certificate-skip local flag suppress one ordinary progress/flush path. Buffered-output state 0x1100 stores its continuation in private 0x164 and restores it after successful backend commands. Literal option bits 0x00400000/0x00800000 and private bits 4/0x10 alter completion/cleanup paths; their product-level intent is not assigned here. Method setup/direction initialization return handling is exactly the driver’s call flow, not independent proof of derived material correctness. Callback progress temporarily exposes the prior state and restores the selected next state. Nested state changes and external callbacks remain unexecuted.

## Parser, key ownership and failure limits

The shared message reader supplies completion and maximum lengths, but these local parsers still read some fixed fields before their own minimum-length checks. Their observed comparisons must not become a blanket assertion that arbitrary short input is safe. CertificateRequest clamps a count above seven instead of skipping the full original count, which changes where its next length is read. Its permissive option accepts only particular failures; it does not waive all list/parser errors. ServerHelloDone’s alert-plus-success behavior is recorded literally.

ServerKeyExchange clears old temporary key fields first. Newly parsed RSA/DH objects can become credential-bundle fields before signature authentication finishes; common failure therefore does not imply rollback. Bundle allocation also lacks an immediate local null check on one path. The DH parameter setter 701FE0 is tested with zero accepted and nonzero rejected in this caller; its convention is not silently inverted to match an assumed Boolean API. RSA signature recovery uses the two selected digests over client random, server random and parameter bytes; DSA uses the selected single digest. Digest update/final return values on these paths do not all gate progress. None of these observations is a reproduced failure or a cryptographic test.

ClientKeyExchange has literal option 0x08000000 that changes an encrypted output byte and 0x10000000 that changes a premaster scratch byte. Their intended test/compatibility meaning remains unknown. Method derivation writes its result length into cached-session storage even when zero; scratch wiping occurs on successful derivation, not every early exit. The certificate-selection callback retains/releases through existing object helpers, whose ownership contracts must be read separately. No guessed recovered function name or algorithm label substitutes for those contracts.
