## Clock and callback limits

Timer workspace20B3E8 contains overflow qword0, handler ID8, generation counterC, allocated count10, free head14, active head18 and current callback handle1C. Constructor clears specified fields only; it does not explicitly initialize all workspace fields, including current callback1C. A record stride40hex uses next0/prev4/token8/flagsC, start10, accumulated18, target20, callback28, savedGP2C and cookie30. Unused/padding fields are not assigned semantic names.

IRQ extended time is((overflow<<16)|unsignedCount)<<(4*(mode&3)), while public readers use shift0,4,8,16 for modes0..3. Initialization does not clamp inputa0 to low2 before OR into mode, though it first clears old low2. This documents actual expressions; it does not prove an active mode3 discrepancy. Pending mode800 increments overflow and writes mode&FFFFFBFF in each explicitly repeated IRQ check. Reader compensation does not mutate the software counter.

The callback result minimum uses unsigned compare against3998hex. Negative values other than-1 are not rejected as signed errors before target addition. The free-on--1 callback branch does not decrement allocated count10 locally; explicit delete does. Current GP is loaded from each callback record without an explicit GP restoration in this body; the enclosing original interrupt ABI remains a dependency. Callbacks may alter state, so list lifetime/reentry and generation validation must be preserved, not replaced by a host timer based only on nominal milliseconds.
