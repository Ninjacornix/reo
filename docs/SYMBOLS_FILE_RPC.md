# File RPC handles, completion and serialized operations

Static File #1 US research, 2026-11-04. [Owned identities](FUNCTION_INDEX.md). No execution, attachment, replay, build or performance measurement.

This family connects the optical size probe in [resident filesystem notes](SYMBOLS_RESIDENT_FILESYSTEM.md) to shared file handles, RPC packets and completion signaling. SDK API identities are probable from packet routing and callers; numeric operation codes and local effects are the stronger evidence. Generated source is absent for RPC primitives0x117818/0x1179E8; their original bodies have now been reviewed separately from owned bytes and existing Ghidra analysis in [RPC core notes](SYMBOLS_SIF_RPC_CORE.md). Original mode0 transport waiting, later file-operation completion and current HLE behavior are separate boundaries.

## Verified completion dispatch

The owned table at0x238B20 contains25 destinations for operation codes2..1A. Specialized branches are2->118330, B->1183D8, C->1184B4 and17/19/1A->118550. All other entries point118598, the common release path. These destinations are labels within0x118268, not additional independently mapped catalogue functions.

The generic RPC client initialization uses a busy retry; SDR initialization in [animation/sound notes](SYMBOLS_ANIMATION_SOUND.md) instead uses alarm sleep. They should not be collapsed into one generic wait implementation without preserving behavior. Static inspection has not established that either retry occurred during playtesting.
