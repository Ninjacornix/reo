## Material, pad and direction limits

71B1A8 is a requested-length derivation loop: its loop-entry test excludes nonpositive requested lengths after context setup. It increments the repeated-letter count before filling the seed, then emits a digest-sized block or requested final residual. There is no local bound on that stack seed count. The final scratch wipe covers the second digest result using its reported length; it does not erase all local material. 71B770's extra allocation byte and unconditional post-derivation1 are observed, not proof that every allocated byte has a meaningful derived value.

71B408 splits the supplied material into two MAC-secret ranges, two key ranges and two IV ranges using the selected method lengths. Its mode12hex/21hex arm uses the first MAC/key/IV side and private64-then44 seed order; the other arm uses the opposite side and44-then64. Bit0 independently chooses the session direction structure and sequence reset, and bit1 is passed as cipher direction. These numeric relationships are preserved without assigning universal client/server enum names.

For the record transformer, extending by a whole block when already aligned follows its explicit `blockwidth - remainder` arithmetic. Only the final padding byte is explicitly written in this routine; unspecified preceding padding bytes are not inferred to be initialized or checked. No live malformed record or padding oracle was tested. The caller-level record MAC and length checks remain separate from local transform behavior.
