# Movie CPU motion prediction and clipped macroblock output

Static File #1 US research, 2026-11-04. Complete owned intervals and both eight-target tables read in **SLUS_207.65**, SHA-256 **06bd5fd7243144cd30cdd0c0023763a369738cb91b177b35e85f6a4782b4ca46**. No target, video playback, frame benchmark, VU execution, attachment or build. This is the resident movie decoder's CPU pixel-prediction path: EE MMI packed integer instructions and ordinary memory accesses, not translated VU microprograms or proof of a rendering bottleneck.

Each kernel takes a seven-word descriptor:0 destination halfword plane,4 byte-window shift,8 first row count,C continuation row count,10 source-byte stride,14/18 two source windows. MTSAB/QFSRV align bytes, PEXTLB/PEXTUB zero-extend samples to halfwords. Luma processes16 samples per row, chroma processes8 for each of two planes, the second plane restarting source+40hex/destination+80hex. Destination row stride is twice source stride. Source-window continuation offsets are80hex luma and140hex chroma. These are literal original tiled layouts, not arbitrary host linear image strides.

Unsigned halfword sums below wrap at16 bits. Define A(x,y)=(u16(x+y+1)>>1), B(a,b,c,d)=(u16(a+b+c+d+2)>>2). The kernels preserve original non-saturating additions and logical shifts; input-domain bounds and equality to a future host SIMD implementation remain to be tested. Averaging variants additionally combine predictor with existing destination; some use `+1`, others use `+(signed16(sum)>0)`, as recorded individually.
