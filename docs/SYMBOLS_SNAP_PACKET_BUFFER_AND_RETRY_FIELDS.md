# SNAP packet buffer, statistics and retry metadata

Static File #1 US research, 2026-11-04. Complete original owned main-ELF bodies; identity in the [central index](FUNCTION_INDEX.md). Builds on [list and pool ownership](SYMBOLS_SNAP_PACKET_LISTS_AND_POOL_ALLOCATION.md), [context retries](SYMBOLS_SNAP_CONTEXT_LIFECYCLE_AND_RETRY_QUEUES.md) and [network clock conversion](SYMBOLS_SNAP_RTC_AND_COUNT_DERIVED_CLOCK.md). No runtime behavior was tested.

Addresses and field offsets are hexadecimal. Packet payload starts2C; unsigned16 metadata8=allocated size,A=class,C=length,E=flags. Word fields10..28 are reset together. Word20 is a retry count because1DB290 increments it and compares it to the context retry limit; the three due-time components14/18/1C are named by their use, with original individual names unknown.

Metadata accessors are deliberately scoped to packet fields whose connected reset, pool and retry users were read. The subsequently closed [socket/datagram path](SYMBOLS_SNAP_SOCKET_DESCRIPTORS_AND_DATAGRAM_SERVICE.md) also uses packet10 for source address and packet1C for source port. Thus the retry-delay label describes that offset's retry use, not every packet instance. Unknown original field names remain unknown. These are static interface contracts, not native translations or claims of observed cost. Constant-only1F2AE0 remains outside semantic credit until its subsystem role can be established.
