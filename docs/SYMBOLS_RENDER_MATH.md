# Rendering math mapping: projection, transforms and VU0 helpers

Static research, 2026-11-03. File #1 US SLUS-20765, main ELF SHA-256
`06bd5fd7243144cd30cdd0c0023763a369738cb91b177b35e85f6a4782b4ca46`.
No game, build, replay, live memory read or debugger attachment was performed.
Original entry boundaries and instruction masks determine each narrow operation.

These routines use EE scalar floating point and VU0 macro instructions. They are
not the separate VU microprogram admission/replay catalogue. Naming them does
not establish that they are interpreted hotspots or justify replacing arithmetic
with a host math library. VU ACC/Q behavior, exceptional inputs, masks, load/store
order and shared template 0x294E00 remain part of each replacement contract.
A zero-divisor or degenerate-vector guard absent from the original cannot simply
be invented as an equivalent optimization.

## What this establishes for optimization planning

Projection/setup work, simple basis operations, perspective point transforms and
orthonormal reconstruction are separate families. The functions differ in
whether they preserve W, translation, source aliases and operation order. They
are useful anchors for caller mapping and future timing/replay tests; no native
math override or performance result is claimed here.
