No game, build, replay, network request, live-memory read, attachment or benchmark occurred. No concrete primitive algorithm is assigned solely from an eight-byte block or key-schedule shape.

The first family stores original vector, current chain and scratch pointers at **+0/+4/+8**, with byte width **+C**. Forward work XORs plaintext with chain before selected primitive callback and adopts output as chain. Reverse work applies reverse primitive, XORs previous chain, then adopts original ciphertext. This is strong static evidence for **CBC-style chaining**. The second mode uses scratch **+0**, width **+4**, and directly transforms each block without chaining, consistent with an **ECB-style adapter**. Provider/primitive identities remain separately selected.

Block loops load/store eight bytes per inner step and four-byte words for XOR. They trust positive, suitably aligned block widths and selected callback contracts. No local zero-width progress guard is added in these bodies, and block callback return values are not used as status. This is a later validation boundary, not a reproduced bug or performance finding.

## Sixteen-round primitive closure

Following the setup and transform callees establishes a **DES-like sixteen-round Feistel family**: eight six-bit table lookups, two28-bit key halves shifted by1/2, sixteen eight-byte subkeys, pre/post bit permutations and a three-stage composition. Owned round-table prefix at0x70A4D0 is `00820200,00020000,80800000,80820200,00800000,80020200,80020000,80800000`. This is an algorithm hypothesis from exact structure, not recovered original symbols or a known-answer verification. No host implementation was run.
