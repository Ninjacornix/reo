## Interpretation for earlier mappings

Mode0 in original SifCallRpc already waits for transport completion, while file wrappers can separately wait for their file-operation callback and result. Those are different completion boundaries. SDR uses mode1 and its own completion callback/semaphore. Current HLE bindings can service operations differently, so a source-only spin/wait finding is not evidence of measured native cost. The Ghidra pseudocode is analysis output, not tested replacement C++.
