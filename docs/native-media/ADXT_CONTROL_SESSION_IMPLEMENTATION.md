# Native finite media control owner evidence

One native owner now enrolls and retires the actual phased players, independently
indexed service tables, shared clock/key contexts and one output session. GCC15.2
and bundled LLVM21.1.8 pass the ownership cases and all **6,706 distinct finite
imported payloads** among **8,910 ADX references**. **Stage3 remains open.** No game,
audio device or ISO was opened; no production/default selector changed.

The [contract](ADXT_CONTROL_SESSION_CONTRACT.md) replaces the previous test
driver's manual table manipulation. Session/generation keys are the public
control capabilities. Every successful open constructs all four strong ports
before membership publication. Invalid/occupied indices refuse before producer
construction. Failed construction retires its consumed producer and restores
an already established peer mix order. No mutable player/producer/clock/table
alias escapes. A caller still supplies the reconstructed mix order explicitly.

The48-case finite matrix spans rates, channels, tiny and unaligned totals and
multiple source windows. Additional checks cover foreign/default/stale keys,
slot reuse, invalid/colliding indices, constructor rollback, full-order admission
before any source poll, three-peer pause/resume, actual blocked-source retirement,
reserved indices during pending joins, peer output progress and retry after an
actual provider-detach refusal. Per-stream retirement returns a copied final
source/output snapshot; only actual source completion frees indices/generation.
One whole-session provider join follows all source retirements and is idempotent.

Three compiling negative controls fail under both compilers: removing generation
validation, freeing indices before a pending source joins and skipping restoration
of an established mix order after a failed open. Both parent Release CTest targets
pass. The native parent project registers48 suites, not48 migrated subsystems.
The first GCC parent compile rejected several densely written lines under the
existing indentation warning policy; those lines were split before the freeze.
No warning policy was weakened.

The actual import runs reuse the unchanged verified Windows mount, real retained
parent archive tails and the full independent inventory/decoder baseline. Every
finite payload count/digest, terminal raw-clock ratio and actual source/producer
retirement passes. One final detach/stop/unload occurs, occupied producers and
control records end at zero, and the import/source/frozen input identities remain
unchanged. All8,910 complete result rows match across compilers, including padding.
Deterministically buffered model consumption has zero underruns/skips; it is not
an audible-output, real-time or stutter measurement. The89 loop references resolve
but are not admitted to complete player playback.

Worker waiting changes control visits: GCC records1,859,732 visits/3,719,464 DTX
scans; LLVM records1,866,651 visits/3,733,302 scans. Both preserve exactly two
scans per visit. The comparator retains both differences explicitly. They are
neither device frames nor game updates and do not establish a speed difference.

The qualification pins native inputs, unit/negative results, both parent builds
and full asset receipts beneath:

This is an independently usable finite native media owner. It is not a complete
guest ADXT adapter, bank/movie session or original DMA/RPC implementation. The
discard/global-service clock branch still refuses, and game selection, LSC,
bank/packet aggregation, movie consumers and controlled game transitions remain
required before stage3 completes. Gameplay, rendering/platform reconstruction
and final compatibility-runtime removal in stages4–6 remain required afterward.
