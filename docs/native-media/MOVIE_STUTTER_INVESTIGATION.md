* Tail line719 records `[vblank-slow] 1448595 us, lastOwner=6 tick=11160 catchup=4`.

### Meaning of the PC and rational fields

`0x1179E8` is the original `SifCallRpc` entry, not a movie decoder or scheduler
poll. The owned ELF's first word is`27BDFF40` (`addiu sp,sp,-0xC0`), an ordinary
function prologue. Catalogue
`recomp/config/outbreak_ghidra_functions.csv:520` owns
`1179E8..117BDC` (500 bytes). The configured skip and sealed
`reo_override.cpp:1705` replace it with
`ps2_syscalls::sceSifCallRpc` → `RPC.cpp::SifCallRpc`.
Original `sceCdRead` at`101788` calls it at`101900`, word`0C045E7A`; delay-slot
`101904` yields return address`101908`. These words were checked in File #1 ELF
SHA-256`06bd5fd7243144cd30cdd0c0023763a369738cb91b177b35e85f6a4782b4ca46`.
The [DVCI boundary](../native-resources/DVCI_OWNER_BOUNDARY.md) already documents
that this RA identifies the CD-read RPC call site, not a particular higher-level
stream or movie. Native async is disabled here. `RPC.cpp:1580` holds its recursive
RPC mutex across the bridge; `reo_hw_bridge.cpp:2989..2998` can synchronously
reach `readCdSectors` and its `m_cdvd->read_sectors` call. This makes synchronous
read/RPC ownership a concrete suspect for the long event, still unproven without
the actual read duration and entry/exit correlation. Do not simply release guest
ownership while retaining the RPC mutex; the historical deadlock described in
[SCENARIO_RUNTIME](../SCENARIO_RUNTIME.md) remains relevant design evidence.

Sealed `reo_override.cpp:1369..1393` runs the original status query first, then
reads decoder `F08/F0C` as`time` and`F00/F04` as`decoded`; `ns` is
`steady_clock::now().time_since_epoch()` in nanoseconds, not Unix time. Emission
is gated by at least60 guest VSync ticks since a shared last-log tick; it is not
an exact1Hz sampler. The text includes no decoder handle or generation.

`F08/F0C` is the cached rational selected movie clock (`CC0+248/24C`), described
in [clock mappings](../SYMBOLS_MOVIE_CLOCKS_AND_TIMECODES.md). `F00/F04` is latest
movie-position metadata (`CC0+240/244`): original`16F338` only raises it when
the published picture-position numerator is greater, then stores the scale.
See [timestamp publication](../SYMBOLS_SOFDEC_VIDEO_SKIP_USERDATA_AND_TIMESTAMP_PUBLICATION.md).
The log label`decoded` is therefore **not a decoded-picture counter**. Neither
rational counts real display scanouts, and timestamps/sentinel/state epochs must
be respected before comparing differences. Approximate native/recompiled
function names in the mapping notebooks do not establish runtime bottlenecks.

## Screenshot confound and screenshot-free repeat

The original run sets`REO_GPU_SHOT_EVERY_SECONDS=5`, and the incident preserves
`gpu-shot-46.bmp` at tick13784. Sealed `reo_bootstrap.cpp:1105..1131` schedules
up to128 captures and writes BMP bytes before scheduling the next interval.
`parallel_backend.cpp:1087..1092` performs the capture inline on the GS owner.
`resident_dxgi_presenter1c.h:300..344` reacquires the shared DXGI target, copies
GPU shader output into a host buffer, submits/presents, **waits the copy fence**,
maps/copies bytes, and returns them for synchronous BMP output. This is added
work with a real GPU wait; its duration was not recorded. Periodic capture can
disturb pacing, but proximity to a screenshot is not a demonstrated cause.

separate shader inventory written/closed during initialization. In the frame
CSV, `scanout_ns` follows `gs_->vsync` return, not physical scanout;

Their interval includes presenter preparation/attach/latency handling. Frames
without presentation have zero optional markers. The trace excludes all work
before `parallel_backend.cpp:999` begins the frame span. The analyzer's
`sampled_movie` classification uses adjacent, nearby advancing rational samples;
without decoder/generation identity it remains approximate and cannot exclude
every monotonic generation change. Its counts are not game FPS or a count of
unique movie pictures.

does not provide all the elapsed times or end-to-end picture/display joins above.

## Minimal next evidence, before changing scheduling

1. Reuse the completed screenshot-free baseline and paired native-on repeat,
   preserving executable hash, input route, visibility changes, source selection,
   clock epochs and dropped-record counts. Compare symptoms first. A native-on
   improvement alone does not isolate a specific adapter among several enabled
   subsystems. Keep the original baseline available for narrower follow-up.
2. For a no-build, narrowly bounded CD suspect check, existing
   `REO_CRI_SERVER_SLOW_MS` enables slow-read durations in
   `ReoHwBridge::readCdSectors`, with LSN/count and a200-record cap, and existing
   CRI dispatcher timing. This also enables the guarded CRI observer's0.5ms
   guest-PC sampler, so measure its overhead; it is not a read-timing-only
   switch. Dispatcher`own_ms` subtracts scheduler waits but can still include
   blocking syscalls. Preserve emitted timestamps/sequence association;
   surrounding text alone may still leave exact overlap unknown. Avoid the
   test-delay variable and avoid logging every read/RPC poll.
3. In a future sealed candidate, add fixed-size, bounded memory records with a
   common monotonic clock: numerical request enqueue→callback start→end,
   generation/event/picture identity, first-not-ready→ready duration and reason
   transitions, copied/parsed byte offsets and pending bytes/output-slot count.
   Aggregate retry counts per event and record state changes/completion, rather
   than printing every retry. This splits owner queue delay, input starvation,
   host parse/decode submission cost and actual GPU-readiness latency.
4. Add elapsed spans around existing IMAGE batch/nonbatch fence waits and frame
   release, plus GS queue record kind/serial and publication/enqueue/dequeue
   timestamps. Correlate them with the next backend frame span and its capture
   tick. This directly tests the large intervals outside current frame spans.
   Preserve current fences and original return order during measurement.
5. Include selected decoder handle/generation/state, rational-clock selection,
   movie picture identity and PCM starvation counters on bounded events. A host
   present receipt should carry the actual picture identity if unique-frame
   delivery is to be measured. Add GPU query timings only if needed after the
   CPU/queue split; queries must not introduce a new synchronous wait.

All proposed producer records should be nonblocking, include overflow/drop
counters, and export away from game/GS critical work. Report unknowns when a
buffer was absent, saturated or failed to export. None of this evidence supports
changing the original movie clock, dropping frames, enlarging queues blindly,
removing consumer fences, or attributing prerecorded-movie behavior to
in-engine cutscene rendering.
