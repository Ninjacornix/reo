# Live queued ADX source evidence

The bounded native input now connects the qualified LSC queue to one existing
encoded ring, actual asynchronous worker, seamless decoder, phased player and
shared output session. This is an isolated implementation; production selection,
audible output and complete original scheduler parity are not claimed.

The catalogue retains sealed single-clip preparations. Keys bind to their owner;
legacy sequence numbers cannot authorize access. The fixed virtual origin is an
address budget. It refuses direct reads, and its exclusive backend accepts only
actual retained sector ranges. An unavailable range declines without fabricating
bytes. No producer overwrites unread encoded storage or resets its incarnation.

File progress is derived after actual ring publication. A worker completion alone
cannot complete a file. Journal reclamation requires both actual encoded
consumption and the decoder's actual seamless sample base. The decoder waits for
the next header when a queued read is pending. A bound stop is performed through
session retirement: output fence first, accepted read disposition, then worker
join. Emergency cleanup remains separately observable.

Both GCC 15.2 and pinned LLVM 21.1.8 passed all 6,706 distinct finite imported ADX
payloads in 421 live sequences. Complete per-clip accepted PCM matched the earlier
independent finite-decoder baseline: 1,198,405,644 channel samples and
2,396,811,288 PCM bytes. Complete clip, clock, source and fence observations
matched across compilers; no padding-row differences or model-output underruns
were observed. Scheduling counts remain observations, not speed measurements.
Actual installed V1 resources were mounted and hashed; the ISO was not opened.

The owner suite covers late enqueue, blocked next-header reads, exact-one pause,
repeat arguments 1/2/257, notification enqueue, full queue/catalogue refusal,
foreign and duplicate binding, direct-origin refusal, private read failure and
retirement with an actual blocked worker while another stream continues. Four
counterfactuals are detected by both compilers: missing next-header wait, treating
submission as file completion, claiming worker join at stop, and missing origin
identity. The first test design's mutation of backend join was unreachable while
the source owner held a pending read. That unsuccessful negative is preserved in
`build-native-sjuni/adxt-lsc-input/qualified-{gcc,llvm}-v1`; v2 moves it to the
observable stop path. It was a test-design gap, not a reproduced runtime failure.

Single-clip validation was factored from immutable sequence preparation. Actual
decoder headers still drive decoding; prepared metadata never supplies PCM or
injects predictor output. The immutable sequence suite now has 926 assertions.
Eleven selected inherited player bodies remain byte-identical; four explicitly
reviewed extensions cover the actual seamless clock offset, cumulative evidence
prefix and live-input stop/final-source observation. Legacy absence normalization
is recorded separately from actual body identity.

The machine-readable qualification retains exact source manifests, compiler and
executable identities, receipts, negative controls and parent-suite logs. Earlier
qualification inputs are preserved under
`build-native-sjuni/adxt-lsc-input/qualification-inputs-v1`; the only subsequent
change to those inputs is the corrected negative-control verifier. Imported live
corpus receipts retain their own complete source hashes. Historical qualifications
are preserved as ancestors rather than relabeled as new game evidence.

The initial profile admits matching mono/stereo clips at qualified sample rates,
an 8192-byte request capacity, minimum threshold 6553 and actual end records/tails.
It refuses bound bare stop/restart, arbitrary thresholds and recovery after a
source error. Source/LSC polling precedes the audio service group; full original
global audio/file/LSC scheduling remains unimplemented. Bank/packet aggregation,
movie control/source/frame lifetimes, game ABI integration and controlled game
transitions still gate stage 3. Gameplay reconstruction, graphics/platform
migration and compatibility-runtime removal remain stages 4–6.
