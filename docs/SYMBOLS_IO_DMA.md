## Progress ownership and naming hazards

Read submission 0x101788 sets busy before the asynchronous RPC and leaves its
release to 0x1004D8 -> 0x100298. The latter signals semaphores and clears state.
A successful request return is not evidence that the data is ready. A caller
which blocks the worker or callback responsible for these writes can prevent
progress; this mapping alone does not establish that such a deadlock occurred.

0x100B70 is N-command acquisition/binding, despite an old scePadPortOpen override
label. 0x100838 is file search, despite historical DMA-flush comments. Original
body and request identity take precedence over those labels. No override was
modified as part of this mapping.

The six entries at main-ELF table 0x241BF0 were read as little-endian words from
the identity-checked file. These are local branch destinations within 0x18CFB0,
not six new functions, and do not count as additional mappings.
