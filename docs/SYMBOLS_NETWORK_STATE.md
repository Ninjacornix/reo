Following0x1CBBC0/0x1CBC60 into0x1E5008 resolves an earlier uncertainty: successful return from those wrappers is the requested size,after synchronous payload copy and local descriptor enqueue. It is not a socket call reporting an arbitrary partial byte count. The queue flushers consuming the requested span therefore do not by themselves prove a partial-send bug.

A different boundary remains open:0x1CC140 overwrites its incoming capacity argument and drains its internal cursor into the supplied output. Valid producer/buffer invariants need to be established before calling this an overflow or adding a bound that might drop data. No incident was reproduced,and this network family may not execute during offline play.
