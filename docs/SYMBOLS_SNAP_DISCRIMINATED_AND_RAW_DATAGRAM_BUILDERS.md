Successful header construction appends to ready queue; child currently ignores append status, so a reported0 does not prove actual delivery or even independently prove queue insertion.

Tokenized requests install the specified callback only after successful header/queue return, return the old unsigned token and increment its byte modulo256. Untokenized callback senders install the callback after success and explicitly return0. Raw senders install no callback. All successful returns are construction/queue outcomes, never acknowledgement or socket-transmit results.

The discriminated blob sender copies the full32-bit a3 count, while the reserve/enqueue count is low16(a3+4). It performs the optional first-word conversion even when a3<4, including zero. The literal4E414D45 discriminant matches [selective inbound union conversion](SYMBOLS_SNAP_CONTROL_PAYLOAD_BYTE_ORDER.md); this supports a name-versus-word union layout without original field names. Caller flags are ORed literally withA000/A400 and not sanitized to an independently proven set.

1E4818 stores t1/t2/t3 in the frame and walks subsequent8-byte ABI slots; only each slot's low32 word becomes a destination word. It begins by testing signed index0<count, not decrementing an unsigned zero. Negative counts skip element emission but still enter shifted/modular length calculation and blob copy. 1E4B38 has the same guarded loop with an explicit caller descriptor. Neither has a count maximum, input-vector extent or output-size-overflow check. Full32-bit blob copy lengths versus low16 packet lengths require caller bounds; no malformed caller inputs or production reachability were established.

The type10 route's count/vector prefix and typeF's direct blob are distinct layouts. They should not be collapsed into a host memcpy replacement, and their sparse flags cannot establish a specific gameplay transport mode without callers. No performance cost or slowdown attribution was measured.
