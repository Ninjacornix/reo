The graph has several distinct policies. Policy 0 examines four ranked candidates at the root but follows only the first ranked candidate recursively; policy 1 examines only the first ranked candidate at both levels. The other dispatcher branch performs a four-neighbor cost search with 10000 sentinel. Replacing these with a single generic shortest-path implementation would change admission, occupancy, tie behavior, failure outputs and potentially gameplay.

Possible future measurement boundaries are the 16,384-slot occupancy clear, repeated candidate/link scans, pairwise candidate sorts and recursive cost searches. This identifies where counters could be useful; it does not establish that any of them is hot during the player's incident. The unchecked empty-candidate path, byte-truncating link-id swap, incomplete region-priority sort and shared-search scratch are static behaviors to reproduce and validate before considering any fix. No optimization or correctness patch was applied.
