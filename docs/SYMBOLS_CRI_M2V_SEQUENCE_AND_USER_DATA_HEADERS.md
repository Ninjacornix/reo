The scalar sequence-field widths identify a conventional MPEG sequence-header layout, but marker bit18 is recorded without requiring1. Matrix flags merely control advances through two64-byte areas in this metadata parser; no coefficient table is copied or installed here. The intra skip refills the bit reader as needed, while the non-intra skip can advance its prefetch pointer without reading each skipped word. Correct quantization-matrix application elsewhere is outside this function's role.

All three header parsers align the supplied pointer downward to4 bytes and prefetch words using byte loads, potentially reading up tothree bytes before the supplied address and additional lookahead after consumed fields. No source length accompanies these entries, so accessible prefix/lookahead is a caller contract. Their common return calculation preserves the literal formula:let `b=(prefetchPointer-original)*8+bitOffset`;result=`original+trunc0((b-57)/8)`, implemented with+7 bias before arithmetic shift when negative. This is consumed-position evidence, not a complete stream bounds proof.

The user-data forwarder resolves previously ambiguous fields:handle11C is a copy destination,120 capacity,124 copied length;none is an error callback. Indexed records atEC contain SJ stream,F0 completion callback,F4 userdata for index0,with12-byte stride. The companion backend/header notebooks were corrected accordingly. Error callback storage remains the separate handle4/8/Ch record described in [backend/pool](SYMBOLS_CRI_M2V_BACKEND_DISPATCH_AND_POOL.md). Initial chunk copying trusts returned chunk lengths, even if a provider returns more than requested; at mosttwo chunks are handled, so full delivery is not guaranteed locally.
