# Prepared owned movie timing context

Joins fresh clock construction, selected/cache authority, audio slot/filter,
pause/buffering control, picture requests and admission under one retained owner.
The [contract](../../../docs/native-media/MOVIE_TIMING_CONTEXT_CONTRACT.md) defines
the prepared profile. Native code uses typed state and interfaces; physical
clock/filter projection exists only in the verification fixture.

Both compilers match 40 original workflows / 210 operations, including 250
initial/final snapshots and the complete observed callback sequence. Each
original cohort executes 221,073 instructions and 508 FP steps. The joined
worker checks 64 emitted-word/condition cases, building on the separately
qualified constructor/admission raw-bit evidence. Public generated statements
are audited against the owned ELF. This is current-runtime compatibility, not
a measurement of original PS2 hardware FPU behavior.

The first 37 workflows / 200 operations were frozen before this module existed.
Three workflows were added after the first candidate to exercise counter-clock
queries during frame stepping, nested buffering queries and command property
effects. Candidate hashes were recorded; all earlier original inputs/results
remain identical. The first original runner failed because its nested ABI check
compared against top-level saved registers. It now checks each actual call's
entry values; the failed scopes and old source remain preserved.

One selected-clock owner holds counters, pending work and cache. The pause owner
holds nesting/episodes, and admission owns its separate tracking state. Typed
patches publish pause/step state before component callbacks and preserve their
reported effects afterward. In the executed frame-step workflow, the nested
counter query observes 1601/48000. Selected and buffering calls share retained
guard state, including the actual depth sequence 0,1,2,2,1,0. This qualifies
serialized paired pure hooks, not the global scheduler, thread priority,
arbitrary reentry or the complete eight-player registry.

Native provider refusal is separate from original callback status. An admitted
callback with status 17 still refreshes its result, as in the original. A refused
sample preserves the cache and avoids publishing invented scratch words; tick
effects or explicit callback facts already applied remain. Shared guards still
leave. The context retains itself through an admitted nested component query,
rejects callback-time mutation/detach, and reports native failure separately.
Ten deliberate faults are detected and 32 boundary checks pass. The retention
counterfactual is tested with a guard that avoids destroying an unretained owner,
so failure detection does not require a use-after-free.

The actual native source/decoder/estimator integration test also passes: the
context consumes the real Session estimate through its opaque stream key,
filters it and publishes cache state. After per-stream source retirement, a stale
key refuses refresh while retaining cache and already advanced tick state. The
Session remains retained until explicit join and context release. Its device
provider is a model; no real device is opened. Timing-query detach retains the
providers and is not a movie/source/device/frame stop fence.

The prepared profile uses selectors 0,1,2,5 and rate codes 0–8. Actual/requested
state and property observations remain inputs from external owners; `observe`
does not replace original property admission or the start/end state machine.
ADXT estimator/helper samples, complete buffer predicates, component commands
and error handling are declared ports in original comparison. A component port
does not secretly pause real audio/video. Diagnostic pointer arguments are
normalized to typed clock/property scopes in verification, not treated as a
complete variadic error ABI. Caller scratch/FP register effects are outside the
native value API.

The changed selected/audio/pause/initialization libraries also rerun their prior
546, 89, 305 and four original-case corpora with both compilers. All 65 standalone
suites pass. Run `python game/native/movie_timing_context/verify.py --cxx
<compiler> --output build-native-sjuni/movie-timing-context/<fresh-scope>` for
the joined comparison, fault controls and source-identity checks.

No game was launched or production path selected. Complete buffer/skip/frame
predicates, actual audio/video commands, source/frame ownership, full movie
construction/stop/rebuild, real scheduler binding, coherent game adapter and
representative transitions still gate stage 3. Gameplay, graphics/platform and
complete compatibility removal remain stages 4–6.
